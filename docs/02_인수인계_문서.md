# 02 인수인계 문서 (AI A 종료 시점 작성)

> 대화 전문 없이 **AI B가 이 문서 + 저장소만으로** 기능을 완성할 수 있도록 남기는 7항목 인수인계 문서.
> AI A는 세션 종료 직전 이 문서를 실제 상태에 맞게 채운다. 항목을 비우거나 삭제하지 않는다.

## 1. 목표 (Goal)
- **원래 목표**: 실시간 정보판 화면 우측 상단에 데이터 신선도 배지(fresh/stale/unavailable)와 경과 시간(ageSeconds) 표시.
- **이번 세션(AI A)에서 달성한 목표**: `DataStatus` 투영, 1초 경과 계산, 접근 가능한 배지, dashboard topbar의 fresh 렌더까지 완료했다.

## 2. 현재 상태 (Current State)
- **작업 완료된 부분**: `widget.ts` 타입 추가, `freshness.ts`와 단위 테스트, `clock.ts`, `freshness-badge.tsx`, dashboard/CSS 연동. 공개 GitHub 상태 위젯의 기존 Query 캐시로 fresh 상태를 표시한다.
- **코드베이스 현재 상황**: topbar 마운트와 fresh 화면 확인 완료. simulate 장애 분기와 T05 전용 E2E는 의도적으로 미구현이다.

## 3. 실행 명령 (Run Commands)
- 의존성 설치: `npm install`
- 개발 실행: `npm run dev`
- 단위 테스트: `npm test`
- E2E 테스트: `npm run test:e2e`

## 4. 통과 검사 (Passed Tests)
- 고정 검사 10개(T05-C01~C10) 중 현재 확인 ID: T05-C01, T05-C09. `freshness.test.ts`의 fresh/stale/unavailable 및 ageSeconds 증가 단위 검사 통과.

## 5. 남은 문제 (Remaining Issues)
- 실패/미구현 검사 ID와 원인: T05-C02~C08, C10은 AI B의 simulate 분기와 E2E 완료 후 최종 확인 필요.
- 알려진 버그: 기능 코드 버그 없음. 전체 `npm test`는 sparse working tree에서 기존 추적 파일 `src/fixtures/widgets.ts`, `src/lib/server/http.ts`가 물리적으로 없어 기존 suite 4개가 import 실패(새 테스트 포함 29/31 통과). 보호 테스트는 수정하지 않았다.

## 6. 다음 행동 (Next Steps)
- AI B가 즉시 이어서 할 첫 작업: `useEffect + window.location.search` 방식의 simulate 분기를 추가하고 catch에서 `displayPayloadAfterFailure`로 이전 값을 유지해 배지를 stale/unavailable로 매핑한다. 이어서 `tests/e2e/t05-freshness.spec.ts`를 작성하고 C02~C10을 검증한다.
