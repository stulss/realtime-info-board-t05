## 배포처

Vercel (Hobby 플랜)

## 선택 근거

- 저장소가 Next.js이므로 별도 서버 구성 없이 Route Handler와 정적 자산을 함께 배포할 수 있다.
- GitHub `main`과 연결하면 이후 문서·코드 push도 같은 배포 흐름으로 재현할 수 있다.
- 개인 과제의 저트래픽 공개 검증에는 Hobby 플랜이 충분하다.

## 사용자 최종 배포 절차

1. Vercel Dashboard에서 `https://github.com/stulss/realtime-info-board-t05` 저장소를 Import하거나 기존 `realtime-info-board-t05` 프로젝트를 연다.
2. Production Branch가 `main`, Framework Preset이 **Next.js**인지 확인한다.
3. Production 환경변수에는 `LOSTARK_API_KEY`, `EXIM_SERVICE_KEY` 두 개만 등록 (`NEXT_PUBLIC_` 접두사 금지)
   - `LOSTARK_MARKET_ITEM_NAME`, `EXIM_CURRENCY`는 화면 입력값이므로 등록하지 않음
4. Build Command와 Output Directory는 **Auto-detect**를 사용한다.
5. Deploy 또는 Redeploy 후 로그인이 필요 없는 Production URL을 연다.
6. `/`와 네 가지 `?simulate=` 주소를 `docs/검증안내서.md` 순서로 확인한다.
7. 최종 URL을 `docs/03_최종_보고서_및_비교.md` §1과 `docs/검증안내서.md`에 반영한다.

## 알려진 배포 설정 주의점

- Framework Preset이 `Other`이면 Vercel이 `dist` 출력물을 기대해 실패할 수 있다.
- 이 프로젝트는 **Next.js** 프리셋과 자동 감지 출력 디렉터리를 사용해야 한다.

## 대안 검토

GitHub Pages + Cloudflare Worker 프록시도 가능하나, Next.js 단일 스택보다 구성 요소가 늘어나 채택하지 않았다.
