# T05 과제 제출 보고서 원고 v3

> 이 원고는 과제 진행 중 작성된 `AI_3줄.md`, `검증안내서.md`, `00_과제_요구사항_매핑.md`, `01_기획.md`, `02_인수인계_문서.md`, `04_작업_기록.md`, `05_배포.md`의 기록만 재구성했다.

## 1. 프로젝트 목표

과제 4의 실시간 정보판에 데이터 신선도 상태 배지 기능 하나를 추가했다. 정상 응답은 `fresh`, 마지막 정상값이 있지만 최신 갱신이 실패한 상태는 `stale`, 정상값이 한 번도 없는 상태는 `unavailable`로 표시한다. 장애가 발생해도 마지막 정상 데이터와 차트를 지우지 않고, 마지막 정상 수신 시각은 고정한 채 `ageSeconds`를 매초 증가시킨다.

## 2. 설계와 역할

- 설계: Claude Code(Architect/Planner)가 고정검사 10개와 공통 작업 상한을 먼저 정하고, 데이터 계약·화면 동작·수정 금지 경계·두 구현자의 작업 분담을 문서화했다.
- 1차 구현: OpenAI Codex(Primary Implementer)가 `DataStatus`, `toDataStatus`, 공용 1초 클록, 접근 가능한 배지, 정상 경로의 fresh 렌더를 구현했다. 작업 시간은 15분, 사용자 프롬프트는 1회였다.
- 인계 후 완성: Claude Code(Secondary Implementer)가 `?simulate=` 장애 분기, 이전 정상값 유지, stale/unavailable 매핑, T05 E2E 5건을 완성했다. 작업 시간은 14분, 사용자 프롬프트는 1회였다.

## 3. 기술 설계

Next.js App Router, React, TypeScript strict, Tailwind CSS 4, TanStack Query 5, Vitest, Testing Library, Playwright를 유지했고 새 의존성은 추가하지 않았다. 기존 6값 `status`를 내부 계약으로 유지하면서 화면에는 3값 `dataStatus`를 투영했다. `useSyncExternalStore` 기반 공용 클록이 마지막 정상 시각과 현재 시각의 차이를 매초 계산한다.

에러 화면과 성공 화면을 분리하지 않고 단일 화면에서 배지만 교체한다. 외부 API·DB 계층은 수정하지 않았고, 기존 `displayPayloadAfterFailure()`를 재사용했다. `?simulate=timeout|auth|ratelimit|empty`는 기존 장애 검증 API에 연결한다.

## 5. 고정검사 결과

T05-C01부터 C10까지 모두 통과했다. fresh 배지와 경과 초, timeout에서 이전 데이터 유지와 stale 표시, 동결된 마지막 정상 시각과 증가하는 경과 초, auth의 401/403 문구, ratelimit의 다음 갱신 대기 문구, empty의 unavailable 문구, 색상 외 텍스트·aria-label, 전체 E2E 통과를 확인했다.

최종 품질 게이트는 lint PASS, typecheck PASS, 단위 테스트 45/45, build PASS, 전체 E2E 14/14다. 최종 공개 URL에서 T05 전용 E2E 5/5를 다시 실행했고 5개 상태 스크린샷을 `docs/검증스크린샷/2026-08-29T04-21-36Z/`에 보존했다.

## 6. 인수인계와 정정

인수인계 문서는 목표, 현재 상태, 실행 명령, 통과 검사, 남은 문제, 다음 행동, 건드리지 말 것의 7항목을 유지했다. OpenAI Codex가 정상 상태의 타입·계산·배지·화면 연동을 끝낸 시점에서 멈췄고, Claude Code가 대화 전문 없이 저장소와 인수인계 문서만으로 장애 분기와 E2E 작업을 이어받았다.

Claude Code는 세 가지를 정정했다. 첫째, 파일이 물리적으로 누락됐다는 설명과 달리 실제 원인은 한글 경로를 퍼센트 인코딩한 Vitest 별칭이었다. `fileURLToPath()`로 수정해 단위 테스트를 29/31에서 45/45로 복구했다. 둘째, fresh 배지에 경과 초 숫자를 추가했다. 셋째, 클라이언트 시계가 서버 시각보다 뒤에 있을 때 `경과 -1s`가 되는 문제를 0 하한과 회귀 테스트로 해결했다.

## 7. 학생 판단과 AI 3줄

- AI에게 맡긴 일: 신선도 배지, 장애 시 이전 값 유지, simulate 분기, 자동 테스트와 인계 문서 구현.
- 학생이 판단한 일: 에러 화면을 따로 만들지 않고 데이터는 유지한 채 배지만 fresh/stale/unavailable로 교체.
- AI 말을 따르지 않은 일: 파일 누락 진단을 그대로 믿지 않고 저장소를 확인해 비ASCII 경로 인코딩이 실제 원인임을 찾음.

## 8. 검증 안내

첫째, `/`에서 우측 상단 fresh 배지와 마지막 수신 시각·경과 초를 확인한다. 둘째, `?simulate=timeout`에서 기존 데이터와 차트가 유지되고 stale 배지의 경과 초가 증가하는지 확인한다. 셋째, auth, ratelimit, empty를 차례로 열어 권한 오류, 다음 갱신 대기, 데이터 없음 문구를 확인한다.
