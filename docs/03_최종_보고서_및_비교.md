## 2. 짧은 확인 방법 (4줄)
- 어디로 가나요: 메인 대시보드 `/` 및 `/?simulate=timeout`
- 3단계 이내 무엇을 하나요: 우측 상단 신선도 배지의 텍스트·숫자 확인 → 주소창에 `?simulate=timeout` 추가 → 새로고침
- 무엇이 보이면 통과인가요: 장애 재현에도 기존 데이터가 유지되고, 배지만 fresh→stale로 바뀌며 경과 시간이 증가
- 안 될 때 무엇이 보이나요: 빈 화면 또는 "데이터를 불러올 수 없습니다"로 기존 이력까지 사라짐

## 3. AI와 나의 판단 (3줄)
- AI에게 맡긴 일: 기존 정보판을 보존하면서 신선도 배지, 장애 시 이전 값 유지, simulate 분기, 자동 테스트와 인계 문서를 구현하게 했다.
- 학생(나)이 직접 판단한 일: 에러 화면을 따로 만들지 않고 한 화면에서 데이터는 유지한 채 배지만 fresh/stale/unavailable로 바꾸도록 정했다.
- AI 제안을 따르지 않은 일: 인계 문서의 “파일 누락” 진단을 그대로 믿지 않고 확인해, 실제 원인이 비ASCII 경로의 Vitest 별칭 인코딩임을 찾아 수정했다.

## 4. AI A/B 이름 가린 비교표 (측정표)
> 판정 구간에서는 모델/도구 실명을 가리고 AI A, AI B로만 표기한다. 재작업량은 제출 후 채점기가 계산한다.

| 항목 | AI A | AI B |
|---|---|---|
| 사용 모델/도구명 | 가려짐(심사 후 공개) | 가려짐(심사 후 공개) |
| 담당 범위 | fresh 상태까지 (타입·순수함수·배지·topbar 연동) | 장애 분기·stale/unavailable 매핑·E2E·인계문서 정정 |
| 실제 작업 시간 | `15`분 | `14`분 |
| 프롬프트 요청/호출 수 | `1`회 | `1`회 (내부 도구 실행 호출은 약 41회) |
| 고정 검사 실패 오류 회차 수 | `0`회 (C02~C08·C10 미실행) | `2`회 (E2E 1·2차 실패 후 3차 통과) |
| 고정 검사 최종 통과 수 | 10개 중 `2`개 (C01, C09) | 10개 중 `10`개 |
