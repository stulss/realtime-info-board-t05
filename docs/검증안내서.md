# T05 검증 안내서 — 신선도 배지 (30초, 3단계 이내)

> T04 검증 안내서는 `docs/T04_검증안내서.md` 에 보존.
> 목표: 고정 검사 10개(T05-C01~C10)를 육안으로 빠르게 확인하고, 통과 증빙 스크린샷을 남긴다.

## 어디로 가나요
- 공개 대시보드: `[Vercel 배포 주소]/`  (로컬은 `npm run dev` 후 `http://localhost:3000/`)
- 장애 재현: 같은 주소에 쿼리 파라미터만 추가 — `?simulate=timeout` / `?simulate=auth` / `?simulate=ratelimit` / `?simulate=empty`

## 무엇을 하나요 (3단계)
1. `/` 접속 → 화면 **우측 상단** 배지가 `fresh` (초록 ●) 이고, 옆에 마지막 수신 시각과 경과 초(`ageSeconds`)가 숫자로 보이는지 확인. → **[C01, C02]**
2. 주소창에 `?simulate=timeout` 추가하고 새로고침 → 기존 값·차트가 그대로 있고, 배지만 `stale` (노랑 ◷) 로 바뀌며, 몇 초 기다리면 경과 초가 계속 커지는지 확인. → **[C03, C04, C05]**
3. `?simulate=auth` → `?simulate=ratelimit` → `?simulate=empty` 를 차례로 접속:
   - `auth`: 배지 `stale` + "권한 오류(401/403)" 안내 텍스트 → **[C06]**
   - `ratelimit`: 배지 `stale` + "다음 갱신 대기 중" 텍스트 → **[C07]**
   - `empty`: 배지 `unavailable` + "데이터를 가져오지 못했습니다" → **[C08]**

## 무엇이 보이면 통과인가요
- 배지가 **색상만이 아니라 텍스트**(fresh/stale/unavailable)로 상태를 구분한다. 흑백으로 봐도 읽힌다. → **[C09]**
- 장애 파라미터 어느 것을 넣어도 **빈 화면·"불러올 수 없습니다"로 기존 데이터가 사라지지 않는다.**
- `npm run test:e2e` 실행 시 `t05-freshness.spec.ts` 가 전부 PASS. → **[C10]**

## 안 될 때
- 배지가 안 보이면: `src/components/dashboard.tsx` topbar에 `<FreshnessBadge>` 가 마운트됐는지 확인.
- 장애 시 화면이 비면: catch 블록이 `displayPayloadAfterFailure(previous, error, source)` 로 **이전 payload를 넘기는지** 확인 (이전 값을 버리면 안 됨).
- 경과 초가 안 늘면: `ageSeconds` 를 서버 값 그대로 쓰지 말고 1초 클록(`useSyncExternalStore`)으로 `now - lastGoodAt` 재계산하는지 확인.

## 스크린샷 정책 (증빙 필수)
- 위 3단계에서 배지 상태가 바뀔 때마다 스크린샷을 찍는다: 최소 `fresh`, `stale(timeout)`, `stale(auth)`, `stale(ratelimit)`, `unavailable` 5장.
- 저장 위치: `docs/검증스크린샷/<실행시각 UTC>/` — 기존 파일 **수정·삭제 금지, 새 폴더에 누적**.
  - E2E는 `SCREENSHOT_RUN_ID` 환경변수로 실행별 폴더를 자동 생성한다 (`playwright.config.ts`).
- AI A·AI B 각 세션은 자기 세션 종료 시점의 배지 화면 스크린샷을 최소 1장 남긴다.
- 파일명에 검사 ID를 넣는다 (예: `C04_stale_timeout.png`).
