# 01 기획 (T05 설계 문서) — 데이터 신선도 상태 배지

> 과제 4(T04) 시절 설계는 `docs/T04_기획.md`와 `docs/T04_프로젝트_전체기록.md`에 보존되어 있다.
> 이 문서는 T04 코드베이스 위에 **신선도 상태 배지 기능 1개**를 추가하는 설계다.

## 1. 목표

API 응답의 `dataStatus`(fresh / stale / unavailable)와 `ageSeconds`를 프런트엔드가 읽어,
화면 **우측 상단**에 텍스트+아이콘 배지를 띄운다.
통신 장애가 나도 **마지막 정상 데이터를 지우지 않고**, 배지만 `stale`로 바꾸며 경과 시간을 계속 키운다.

근거: `../../과제5_템플릿/퍼플렉시티 조사 사료.md` — "실패한 응답으로 정상 데이터를 절대 덮어쓰지 않고, 갱신 시각과 stale 상태를 명시한 채 마지막 정상 데이터를 제공한다."

## 2. 기술 스택 (기존 유지)

- Next.js (App Router) + React + TypeScript strict / Tailwind CSS 4 / TanStack Query 5
- Vitest + Testing Library + Playwright / Vercel 배포
- **새 의존성 추가 없음.** 기존 `useSyncExternalStore` 1초 클록(`src/components/widget-card.tsx`)을 재사용해 `ageSeconds`를 실시간 계산한다.

## 3. 핵심 원칙 (학생 판단)

- 에러 뷰와 성공 뷰를 **분리하지 않는다**. 단일 뷰에서 배지만 교체한다.
- 에러 대응은 **오직 클라이언트 렌더링 단**에서. `src/app/api/widgets/*`의 외부 API(Upbit 등) fetch 로직과 DB 연동 코드는 수정 금지.
- Toast·모달 알림을 쓰지 않는다. 정직한 배지 + 텍스트 안내만 사용한다(퍼플렉시티 지침).

## 4. 데이터 계약 (contract)

기존 `WidgetPayload`(`src/types/widget.ts`)의 6-값 `status`는 내부 상태로 그대로 두고,
배지는 **3-값 공개 투영(projection)** `dataStatus`를 쓴다.

| dataStatus | 도출 규칙 | 기존 status 대응 |
|---|---|---|
| `fresh` | 최신 정상 응답 수신, `ageSeconds`가 임계값 이내 | `ok` |
| `stale` | 마지막 정상값은 있으나 최신 fetch 실패, 또는 age 임계 초과 | `stale`, `rate_limited` |
| `unavailable` | 정상값이 한 번도 없고 표시할 데이터 없음 | `value === null` 인 `error` |

- `ageSeconds`: `(now - lastGoodAt) / 1000`. **클라이언트가 매초 재계산**한다.
  서버는 기존 `sourceTimestamp` / `fetchedAt`(ISO 8601 UTC)만 내려주면 된다.
  장애 시 `lastGoodAt`은 **동결**되므로 배지의 시각은 멈추고 `ageSeconds`만 증가한다(T05-C05).
- `stale` 사유 텍스트: `lastError.kind`로 분기 —
  `unauthorized` → "권한 오류(401/403)로 갱신 중지",
  `rate_limited` → "호출 제한 — 다음 갱신 대기 중",
  `timeout`/기타 → "업데이트 지연 — 마지막 정상 수신 HH:MM:SS".

## 5. 프런트엔드 상태 관리 아키텍처

```
URL ?simulate=timeout|auth|ratelimit|empty
        │
        ▼
useSimulateParam()  ── window.location.search를 useEffect에서 1회 읽음 (useSearchParams는 Suspense 필요)
        │
        ▼
DashboardWidget (기존)
  ├─ simulate 없음 → fetchWidgetPayload("/api/widgets/*")            (기존 경로)
  └─ simulate 있음 → 1) seed = 정상 fixture(fresh) 즉시 렌더
                     2) fetchWidgetPayload("/api/verification/failure?kind=…")  (실패)
                     3) catch → displayPayloadAfterFailure(seed, error)  ← 기존 함수 재사용
                            · previous.value 유지, status="stale", lastError 설정
        │
        ▼
toDataStatus(payload) → { dataStatus, ageSeconds(live), lastGoodAt, reasonText }
        │
        ▼
<FreshnessBadge>  (신규, topbar 우측 상단)   +   기존 <WidgetCard> 그대로
```

- `?simulate=` → `kind` 매핑: `timeout→timeout`, `auth→unauthorized`, `ratelimit→rate_limited`, `empty→(seed 없음)`.
- `displayPayloadAfterFailure`(`src/lib/client/widget-state.ts`)가 이미 "이전 값 유지 + stale + lastError"를 정확히 수행한다 → **catch 블록에서 이 함수만 호출**하면 C03·C04·C06·C07 충족.
- `empty`: seed 없이 실패 → `value=null`, 이전값 없음 → `unavailable`(C08).
